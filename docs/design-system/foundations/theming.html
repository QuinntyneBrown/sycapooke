Foundation · Heirloom

Theming

Light (ink on paper, terracotta accent) and dark (cream on ink, mustard links) themes from one token file, following the device unless the member picks one.

Overview

Light is :root. Dark is [data-theme="dark"] and the same block inside @media (prefers-color-scheme: dark) for :root:not([data-theme="light"]). Each sets color-scheme so native controls match.

Adding a theme

[data-theme="holiday"] {
  --color-accent: var(--palette-red-600);
  --color-hero-from: var(--palette-red-600);
  --color-hero-to: var(--palette-green-700);
}
  • Override semantic tokens only.
  • Add the theme to contrast-pairs.json runs and fix every failure.
  • Re-export tokens.json.

Heirloom brand palette

After Heirloom’s base tokens, the Heirloom brand palette block adds the paper, ink, terracotta, forest and mustard scales from the Sycapooke landing page, aliases the older cream and sun primitives onto paper and mustard, declares the logo tokens and points every semantic colour token at the new scales for both themes: pop-pink → terracotta, pop-grape → forest, pop-sun → mustard. Light is ink on paper with a terracotta accent and terracotta-700 links; dark is cream on ink (ink-950 canvas, ink-900 surfaces, ink-850 raised) with a terracotta-400 accent and mustard-300 links. The tag logo keeps its terracotta and cream in both themes; the string and wordmark follow --color-fg-default. Type, space, shape, elevation and motion stay Heirloom’s. Sycapooke layout tokens

The Sycapooke layout tokens block at the end of tokens.css names the things only the 12L layout uses (the stone and signal ramps, --color-brand, the photo wells, --font-weight-black, --letter-spacing-display, the showcase and shape tokens, the inverse status icons) and aliases each onto a Heirloom token, so Heirloom stays the single source of the look. It also sets --chamfer: 0px: Heirloom shapes are rounded, so the 12L 45° chamfer is switched off everywhere. A theme never overrides these aliases directly; it overrides the Heirloom semantic tokens they point to (only --color-inverse-* has its own dark values). See Color.

tokens.json

tokens/tokens.json is a DTCG export ($type, $value, aliases as {group.token}, dark overrides under $extensions). Generate it with tokens_to_json.py; never edit it by hand. The Angular app can import it to generate SCSS maps or TypeScript constants.

Do and don’t

  • Do test both themes for every new component.
  • Don’t invert light values for dark; design dark from roles.
  • Don’t reference primitives from components.
