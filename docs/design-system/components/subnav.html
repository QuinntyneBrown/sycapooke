Subnav

Tabs for the pages of one area: a customer's account, or the founder's shop management.

WCAG 2.2 AAStatus: stableSince v0.2

Overview

The subnav sits under the top bar on every account and shop-management page. The customer sees Overview, Purchases, Emails and Settings; the founder sees Shop, Inventory, Sales, Support, Story, Emails and Settings. The application chooses the set from AuthState.isFounder; the server still authorises every page.

Anatomy

  1. NavLandmark labelled "Account" or "Shop management", with a bottom rule
  2. TabA link; the current page carries aria-current="page"

Responsive behaviour

The tabs never wrap. Below 576 px the row scrolls horizontally inside the nav with the scrollbar hidden, so the page itself never scrolls sideways.

Theming

Reads --color-border-default for the rule and the tab tokens for text and the current underline; themes swap them.

Accessibility

Role and pattern

A nav landmark with a unique label (WCAG 1.3.1, 2.4.1). The current tab has aria-current="page".

Keyboard

KeyAction
TabMoves between the tabs.
EnterOpens the page.

Focus

The shared focus ring applies to each tab; a tab scrolled out of view scrolls into view when focused.

Labelling

The nav label names the area ("Account" or "Shop management"); each tab is its own visible text.

Content

One or two words, sentence case: "Overview", "Purchases", "Emails", "Settings". Never "My account".
