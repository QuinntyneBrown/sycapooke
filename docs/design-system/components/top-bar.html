Top bar

The sticky 5rem header on paper at 95% behind a blur: menu button, logo, pill navigation links, the search well, and Sign in with the primary Sign in pill for a guest, only the avatar for a customer, and Inventory plus the primary Sell an item pill for the founder.

Overview

The top bar frames every app-shell page, as the landing-page header does: 5rem tall, paper at 95% behind a 12 px blur, a line underneath. Nav links are pills that fill cream on hover; a guest sees a single primary “Sign in” pill, a customer sees only the avatar (no selling controls), and the founder sees an “Inventory” link, the primary “Sell an item” pill and the avatar. The full search well shows from 992px. The four category links need the width of the xl breakpoint, so they show inline only from 1280px; below that the menu button opens the menu sheet that lists them (L2-062). The bare shell uses a reduced top bar with the logo only. There is no admin shell.

Anatomy

  1. Menu buttonA round cream icon button; aria-label Open menu, aria-controls menu; below xl (1280px) only
  2. Logosy-logo: the terracotta price tag with its italic “S” beside the Fraunces italic wordmark, a link to / named Sycapooke home
  3. Primary navnav aria-label Primary; pill links (--space-2 by --space-4, semibold, cream on hover); aria-current underlines the active category
  4. SearchThe search well (cream pill, line border, one shadow) with a visually hidden label
  5. ActionsGuest: “Sign in” primary pill. Customer: avatar link only. Founder: “Inventory” link, “Sell an item” primary pill, avatar link

Responsive behaviour

  • Below 768px: menu button, logo, search icon button, Sign in (guest) or the avatar (customer, founder). The pill (Sign in, Sell an item) is hidden; those actions live in the menu sheet. Nothing scrolls sideways at 320px.
  • From 768px: the pill appears. The menu button stays; the category links live in the menu sheet.
  • From 992px: the search well replaces the search icon button.
  • From 1280px (--layout-breakpoint-xl): the category links appear inline and the menu button hides.

Theming

Paper (--color-bg-canvas) at 95% over a blur with a line border; pills fill --color-bg-subtle. The tag logo keeps its terracotta and cream in both themes; its string and wordmark follow --color-fg-default.

Accessibility

Role and pattern

A <header> (banner landmark) containing a nav named Primary and a form with role="search". The menu button owns the sheet through aria-controls and aria-expanded.

Keyboard

TabMenu, logo, nav links, search, actions in DOM order.

Focus

The shared terracotta ring; inside the search well the well’s border turns ink instead. Sticky position keeps focused controls visible.

Labelling

Icon-only controls carry aria-label (Open menu, Search). The avatar link is named "Your account, {name}".

Content

Categories: Jewelry, Clothing, Housewares, Electronics. Guest action: Sign in. Customer action: Your account. Founder actions: Inventory, Sell an item, Shop management. Search placeholder: Try “pearl necklace” or “tea set”.

Angular

<sy-top-bar [member]="auth.member()" />

With a customer, sy-top-bar shows only the avatar link “Your account, {display name}”; with the founder it adds the “Inventory” link, the “Sell an item” primary pill and the avatar link “Shop management, {display name}”; without a member it shows the primary “Sign in” pill. The application passes the member from AuthState in @sycapooke/api.
